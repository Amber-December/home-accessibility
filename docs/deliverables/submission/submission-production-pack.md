## 1. 统一创意

**主句**：住进去之前，先替你住一遍。

**结构句**：先住一套，再测一批。

视频和 PPT 共用一条可复测路径：真实商品进入三维空间 → 轮椅使用者执行生活任务 → 任务受阻 → 系统定位对象和余量 → Repair Agent 调整方案 → 同条件复测。

“具身智能验证空间设计”聚焦于实验室模式。试住模式负责回答一套具体住宅能否服务目标住户，实验室模式负责把同一验证方法扩展到住宅集、家具系列和空间变量。

## 3. PPT 素材设计

### 3.1 页面与素材对应

| 页 | 视觉任务 | 必备素材 | 录制/制作方式 |
|---:|---|---|---|
| 1 | 封面：清先住要做什么 | Web 桌面端首页、移动端试住入口、清先住主句 | 桌面端 16:9 截图 + 手机窄屏录屏叠放 |
| 2–3 | 背景：空间表达与单项规范的边界 | 2D 户型图、规范尺寸卡、轮椅任务路径、床尾局部 3D | 以同一颜色标出“规则通过”和“任务受阻” |

| 6–7 | 技术：Agent、仿真和可追溯底座 | Agent 流程、3D 轨迹、碰撞点、诊断卡、标准参数 | 2D 流程图与 3D 住户动作帧组合 |
| 8–9 | 体验：试住与实验室 Journey | 住户卡、任务步骤、人物/情景矩阵、修复前后对比 | 试住使用真实录屏，实验室使用预计算矩阵 |
| 10 | Lux3D：真实商品/任务进入仿真空间 | 商品参考图、Lux3D 模型、尺寸标注、碰撞体 | 使用 IKEA 清单中的 `reference.jpg`、`model.glb` 与验证 JSON |
| 11 | 价值：从家庭问题扩展到空间和产品验证 | 家庭结果卡、设计方案对照、家具系列适配矩阵 | 一张大结论图，四类使用者用短标签呈现 |

### 3.2 2D–3D 视觉节奏

```text
2D 户型/任务解释 → 3D 住户行动 → 2D 诊断证据 → 3D 同条件复测 → 2D 实验室规模化
```

- 2D 承担任务、尺寸、对象、状态和规模化结果。
- 3D 承担住户行动、家具关系、路径、碰撞和前后对比。
- 2D 与 3D 使用同一语义色：青绿=通行，琥珀=余量关注，珊瑚红=受阻，清华紫=品牌与关键动作。
- 页面标题使用结论句；正文控制在一到两行，数字和单位来自真实运行记录。

### 3.3 开场画面

PPT 第 1 页和视频前 5 秒均从 Web 产品界面开始：桌面端展示完整工作台，移动端展示一个可操作的“我能住进去吗？”入口。手机画面使用真实窄屏布局，尺寸建议 390×844；桌面录屏使用 1440×900 或浏览器 16:9 裁切。

推荐字幕：

> 我坐轮椅，能从卧室到卫生间吗？

随后将商品参考图切换为 Lux3D 模型，再切到住宅中的同一件家具。开场第 20 秒内完成产品、真实资产和任务冲突三个钩子。

### 3.4 本地 PPT 模板素材

模板设计说明和预览已整理到 [assets/ppt-templates](assets/ppt-templates/README.md)。推荐使用 `soft-editorial` 作为人物故事和价值页，`emerald-editorial` 作为空间页，`blue-professional` 作为技术页，`signal` 作为失败/修复页。模板提供版式和色彩方向，页面证据仍使用真实产品素材。

## 4. 视频素材设计

### 4.1 主片（2:45–3:00）

| 时间 | 素材 | 画面比例 | 交付 |
|---|---|---:|---|

### 4.2 现场兜底片（60–75 秒）

使用主片中的同一组镜头，保留：Web 入口 5 秒、资产链路 8 秒、失败 20 秒、诊断 12 秒、修复与复测 25 秒。文件需为单个可播放视频，断网时从本地直接打开。

### 4.3 移动端与桌面端的录屏分工

| 端 | 用途 | 画面重点 | 建议规格 |
|---|---|---|---|
| 移动端 Web | 视频钩子、PPT 封面角落、用户入口 | 住户选择、任务提问、开始试住 | 390×844，60 fps，录制触控或鼠标轨迹 |
| 桌面 Web | 完整操作、3D 行动、诊断和复测 | 三栏工作台、3D 视图、结果面板 | 1440×900，导出 1920×1080 |
| 移动端/桌面端并置 | 说明产品覆盖场景 | 手机发起需求，桌面完成空间诊断 | 同一住户、同一任务、同一案例 |

移动端承担“提出需求和开始试住”，桌面端承担“观察空间与解释证据”。两端通过同一案例 ID 和任务状态连接，字幕中保持名称一致。

床模型可作为卧室背景家具；当前床类目录有参考图和 GLB，但部分条目缺少物理验证记录，进入任务判定前需标为“视觉展示”或补做验证。

### 5.2 资产使用边界

- `reference.jpg` 用于 PPT 与视频的商品输入镜头。
- `model.glb` 用于 3D 展示和场景入场。
- `model_spec.json` 用于尺寸、坐标和部件说明。
- `physics_validation.json` 用于展示物理验证状态；字段“passed”仅描述该资产验证记录。
- `source_product.json` 保留商品来源、采集时间和规格；正式提交时按许可要求呈现来源。
- 原始模型目录保留在仓库外部；仓库内清单记录路径、用途和证据状态。

## 6. 制作排期与验收

### T0：案例冻结

确定一套户型、一个轮椅住户、一个连续任务和一件主家具；记录起点、随机种子、镜头、任务状态和真实输出。

### T+1：Web 录屏

完成移动端 390×844 开场与桌面端 16:9 完整闭环录屏；导出无光标版与带光标版各一份。

### T+2：资产与诊断

导出商品图、Lux3D 模型、尺寸/碰撞镜头、失败诊断卡和修复前后对比图；资产清单同步填写来源和验证状态。

### T+3：剪辑与 PPT

按“2D 解释 → 3D 行动 → 2D 诊断 → 3D 复测 → 2D 规模化”剪辑；PPT 每页只保留一个结论，演讲总时长控制在约 6 分钟。

### T+4：稳定性验收

- 主片时长 2:45–3:00，兜底片时长 60–75 秒。
- 前 20 秒出现 Web 产品、真实家具和任务冲突。
- 失败与复测使用相同住户、任务、起点和关键参数。
- 诊断至少展示对象、尺寸/余量、任务状态、依据中的三项。
- 移动端和桌面端画面均来自真实产品界面。
- 视频字幕、PPT 文案和产品界面统一使用“清先住、试住模式 Stay、实验室模式 Lab”。
- 画面不包含邀请码、API Key、个人路径或未登记来源的商品图。
