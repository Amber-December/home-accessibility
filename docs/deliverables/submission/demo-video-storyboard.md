## 1. 视频核心设计

视频主段只讲一条试住任务：

> 轮椅住户进入卧室，在床边完成转身并取用衣物。

场景包含一件具有明确尺寸和通行影响的家具，例如床、衣柜或床边柜。家具先由商品图片进入 Lux3D，再经过尺度校准、碰撞体和交互区域处理，最后进入试住任务仿真。结尾用实验室模式的场景矩阵说明，同一套任务评估可以扩展到住宅集和家具系列。

视频的情绪曲线是：

```text
看起来能住 → 任务开始 → 受阻 → 找到原因 → 改造 → 同条件复测成功
```

## 1.1 开场钩子

推荐使用“三连钩子”，前 20 秒完成产品、人物和冲突的建立：

### 钩子 A：产品先出现（0:00–0:05）

使用 Web 端试住界面，不从 Logo 静态页开始。画面显示清先住品牌、`试住 Stay`、住户卡和任务步骤，用户输入：

> 我坐轮椅，能从卧室到卫生间吗？

字幕：

> 这是一个可以亲自走进去验证的家。

### 钩子 B：真实家具进入场景（0:05–0:12）

从 `ikea-model/` 中选一件带参考图、GLB 和验证记录的家具，快速切换：

```text
商品图 → Lux3D 模型 → 尺度 / 碰撞信息 → 住宅中的家具
```

字幕：

> 这不是一张效果图，它要参与一次真实任务测试。

### 钩子 C：结果反转（0:12–0:20）

先给一帧绿色平面图“路径存在”，随后切入 3D 住户在床尾或门侧停下。

字幕：

> 平面图显示能到达，住户却转不过去。

这三个钩子之后进入完整任务，不再新增人物和场景。

## 3. 现场录屏与预制素材分工

### 3.1 使用产品实时录屏

- 户型整体视角和住户跟随视角。
- 住户执行任务的失败过程。
- 点击风险点查看诊断信息。
- Repair Agent 修改预览。
- 相同任务复测成功。

### 3.2 使用预制素材或动画

- 商品图片到 Lux3D 模型的转场。
- 模型的尺度标尺、碰撞体和交互区域展示。
- 试住模式与实验室模式的结构图。
- 批量实验场景矩阵和结果汇总。
- 片头、字幕、章节标题和结尾 Logo。

### 3.3 网络或服务异常时的替代路径

- Lux3D 生成过程使用已缓存的模型和 10–15 秒生成过程录屏。
- 产品实时演示切换为本地固定户型、固定随机种子和缓存资产。
- 失败与成功使用同一组已验证录屏，保持镜头、旁白和时间线一致。
- 备份视频保持 60–75 秒，可作为现场快速播放版本；完整成片保持约 3 分钟。

## 4. 画面与剪辑规则

- 3D 产品画面保持 16:9，浏览器录屏隐藏无关窗口和地址栏。
- 每个镜头只突出一个动作：进入、转身、受阻、诊断、修改或复测。
- 关键风险点使用局部放大、轮廓线和简短标签；标签内容保持 1–2 行。
- 录屏速度使用实时或 1.25×，任务失败前保留足够等待时间。
- 镜头切换使用短淡入、空间擦除或同位置前后对比，避免频繁旋转镜头。
- 字幕优先呈现可验证事实：对象、距离、任务状态和修改结果。
- 音乐使用低存在感节奏，任务失败处降低音乐音量，复测成功处恢复；旁白始终清楚。
- 关键页面增加中文和英文短标签：`REAL PRODUCT ASSET`、`EMBODIED TASK`、`RETEST`。

## 4.1 2D–3D 转场设计

视频采用“2D 解释 → 3D 行动 → 2D 诊断 → 3D 复测 → 2D 规模化”的节奏：

| 段落 | 2D 画面 | 3D 画面 | 转场 |
|---|---|---|---|
| 开场 | 户型平面图、住户和任务标签 | 镜头进入对应房间 | 从平面图风险点缩放进入三维门口 |
| 商品入场 | 商品图、尺寸和模型状态 | 家具落入住宅并校准位置 | 用同一物体轮廓从 2D 标签切到 3D 模型 |
| 任务执行 | 任务状态条和路径节点 | 住户移动、转向和接近 | 2D 状态条固定在画面边缘，3D 画面保持连续 |
| 任务失败 | 对象、净宽、余量和依据卡 | 镜头停在受阻家具旁 | 从 3D 受阻点拉出一条标线，展开 2D 诊断卡 |
| 修复与复测 | 修改前后差值和方案标签 | 家具移动、住户重新执行 | 保持相同机位，用擦除或分屏展示前后变化 |
| 结尾 | 试住 / 实验室双模式和场景矩阵 | 代表性住宅缩略回放 | 3D 结果缩小成矩阵中的一个样本 |

2D 画面承担解释和节奏控制，3D 画面承担空间证据。参考图中的家居插画可以用于片头、模式页和结尾氛围，任务失败、路径和碰撞结果使用产品真实录屏。

## 5. 旁白初稿

> 住进去之前，先替你住一遍。
>
> 这是一个轮椅住户，准备进入卧室，完成床边转身并取用衣物。
>
> 我们先把真实商品放进空间。商品图片经过 Lux3D 生成三维资产，再校准尺寸，补充碰撞体和交互区域，进入同一套任务仿真。
>
> 任务开始。住户从门口进入，沿着床边接近衣柜。这里出现了受阻。
>
> 清先住把失败定位到具体家具和通道余量，给出可追溯的诊断信息。
>
> Repair Agent 根据失败原因移动家具，随后使用同一住户、同一任务和同一起点重新测试。
>
> 这次任务完成。清先住先在试住模式里解决一套具体住宅的问题，再在实验室模式里用具身智能验证更多空间设计。
