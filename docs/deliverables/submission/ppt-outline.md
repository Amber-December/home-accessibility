## 1. 统一叙事

**一句话定位**

> 清先住提供试住和实验室两种模式：先验证一套具体住宅，再用具身智能批量验证空间设计和家具系列。

**核心命题**

> 同一套仿真底座，把真实住宅里的生活任务变成可追溯、可复测的设计证据。

“具身智能验证空间设计”是实验室模式的技术与价值重点。试住模式负责让住户、家属和设计师先看清一套具体住宅能否完成生活任务。

**现场故事**

王阿姨准备和使用轮椅的父亲共同居住。户型图看起来宽敞，家具摆入后，父亲在“进入卧室、床边转身、取用衣物”任务中第一次失败。试住模式把失败定位到具体家具和通道余量，Repair Agent 调整方案，再用同一住户、同一任务和同一起点复测。实验室模式再把这套验证方法扩展到一批住宅和家具系列。

这条故事线贯穿 PPT 和 Demo 视频。现场主 Demo 运行试住模式的一套稳定案例；实验室模式用预计算场景矩阵、家具系列对照和任务统计承接规模化价值。

### 第 9 页的现场节奏

1. 选择轮椅使用者和“进入卧室并取用衣物”任务，约 10 秒。
2. 展示一件由商品图片生成并校准的家具，约 15 秒。
3. 运行任务，人物在床尾或门侧受阻，约 25 秒。
4. 点击问题点，展示具体家具、净宽或转身余量，约 15 秒。
5. 启动 Repair Agent，展示家具移动或替换，约 15 秒。
6. 用相同条件复测，展示路径完成和指标变化，约 15 秒。

## 3. 页面文案与视觉规则

- 标题写判断结论，例如“家具摆入后，连续任务仍可能失败”。
- 每页只保留一个视觉判断，正文控制在 35 字以内，证据数字只使用已实测结果。
- 视觉主色沿用清先住：清华紫作为品牌识别，青绿色表示通行，琥珀色表示关注，珊瑚红表示失败或高风险。
- 背景使用暖白和浅灰，3D 户型使用低饱和材质，风险点使用明确轮廓和局部高亮。
- 页面结构采用“左侧结论 + 中央空间画面 + 右侧证据”或“大画面 + 一行结论”，减少卡片堆叠。
- 动效只服务于路径、镜头、失败点和前后对比；录屏画面保持稳定，避免连续旋转和无关粒子。

### 3.1 参考图的采用方式

参考图适合提供“家居编辑杂志”的视觉气质：暖白页面、深色墙面、低饱和家居色、手绘式装饰线和大幅空间图。清先住沿用这套气质，同时把信息层级收回到产品证据上。

推荐色彩关系：

| 层 | 建议 |
|---|---|
| 页面底色 | 暖白、浅灰和很浅的粉灰，用于建立居住感 |
| 空间块 | 深墨绿或深灰绿，用于户型背景和章节封面 |
| 家居辅助色 | 灰粉、鼠尾草绿、木色和雾蓝，用于 2D 插图和素材标签 |
| 产品识别色 | 清华紫，用于 Logo、路径起点、关键按钮和结论标记 |
| 评估语义色 | 青绿表示通过，琥珀表示余量偏小，珊瑚红表示失败或高风险 |

手写或脚本字体只用于章节短句和情绪引导，产品标题、数字、规范和任务结果使用清晰的无衬线字体，保证演讲现场可读。

### 3.2 2D–3D 结合规则

把 2D 作为解释层，把 3D 作为证据层：

| 内容 | 2D 表达 | 3D 表达 |
|---|---|---|
| 产品结构 | 试住 / 实验室双入口图 | 两种模式对应的空间截图 |
| 户型输入 | 平面图、房间标签、尺寸标线 | 墙、门、家具和可通行区域 |
| 任务过程 | 任务状态条、路径节点和事件图标 | 住户移动、转向、开门和取用 |
| 失败原因 | 对象、净宽、余量、依据的证据卡 | 镜头推近问题家具和受阻位置 |
| 改造前后 | 左右对照、差值和结论 | 同一视角的模型、路径和门扇变化 |
| 实验室模式 | 住宅矩阵、家具系列对照和统计图 | 代表性住宅缩略图和失败案例回放 |

每页优先使用一个“2D 框架 + 3D 窗口 + 2D 证据”的组合：2D 框架交代看什么，3D 窗口展示发生了什么，2D 证据说明为什么得出这个结论。2D 与 3D 使用同一套颜色语义和对象命名，观众可以从平面图的风险点直接对应到三维中的家具。

### 3.3 页面落地示例

1. **封面**：深色空间背景或 3D 户型大图，左上放清先住标题，底部用一条 2D 路径线连接“失败”与“复测成功”。
2. **问题页**：左侧为暖白平面图，右侧嵌入床尾或门侧的 3D 近景，下方放一句任务结论。
3. **双模式页**：两张 2D 模式卡各放一张 3D 缩略图，试住突出一套住宅，实验室突出住宅矩阵。
4. **Lux3D 页**：商品图、模型线框、校准尺寸和碰撞体用 2D 四步串联，中心放一张真实 3D 家具渲染。
5. **实验室页**：主画面使用 2D 场景矩阵，右侧放具身智能在代表性住宅中的 3D 轨迹回放。
6. **现场 Demo 页**：让产品录屏占页面 70% 以上，2D 字幕只标注当前任务、失败对象和复测结果。

视频沿用同一规则：2D 平面图开场，镜头进入 3D 住宅，失败时回到 2D 诊断卡，修复后再回到同一 3D 视角，结尾用 2D 实验室矩阵承接规模化验证。

### 3.4 开场使用 Web 产品界面

开场可以先放当前 Web 端产品界面，让评委先看到“这是一件可以操作的产品”，再进入故事和技术。建议截取 `web/index.html` 的试住入口：清先住品牌、试住 Stay、住户选择、任务步骤、3D 视图和右侧诊断面板同时出现。

开场画面顺序：

1. Web 产品界面静止 2 秒，显示“试住 Stay”和任务步骤。
2. 用户输入或选择一句需求：“我坐轮椅，能从卧室到卫生间吗？”
3. 任务卡展开，3D 住宅加载，住户从起点开始行动。
4. 画面切入受阻位置，标题出现：“这套房，看起来能住吗？”

当前 `web/css/app.css` 是桌面三栏布局。PPT 可直接使用 16:9 Web 截图；如果需要移动端视觉，需要先补真实的窄屏布局，再录制 375×812 或 390×844 的界面。手机外框只作为呈现容器，画面中的交互仍应来自真实 Web 版本。

### 3.5 IKEA / Lux3D 资产的使用方式

`ikea-model/` 现有约 15 类、100 个宜家模型，包含床、床边桌、衣物收纳柜、书柜、沙发、餐桌和餐椅等类别。优先选择同时具备以下文件的模型作为 PPT 和视频素材：

- `reference.jpg`：商品图或输入参考。
- `model.glb`：可进入 Web 端的展示模型。
- `model_spec.json`：尺寸、部件和生成信息。
- `physics_validation.json`：物理或碰撞验证记录。
- `visual_metadata.json`：呈现和来源说明。

推荐素材组合：床 + 床边桌 + 衣物收纳柜。它们能对应卧室进入、床边转身、靠近和取物任务。PPT 中展示商品图、Lux3D 模型、尺寸或碰撞证据和住宅内的实际摆放；视频中只选一件家具做完整链路，其余作为实验室模式的系列缩略图。

素材进入提交物前，将选定模型复制到 `submission/assets/ikea/`，同时保留每件模型的来源、许可、模型 ID 和验证状态。没有验证记录的模型可用于视觉展示，进入任务判定前需要单独标注状态。

## 6. 现场边界与表达

- 使用“风险筛查、设计决策支持、任务仿真验证”等表述，结果依据项目已核对的标准和仿真规则。
- 资产生成、尺度校准、碰撞体和交互区域分别展示，避免将生成模型直接等同于可验证资产。
- 批量实验使用预计算结果和真实统计；现场不等待大规模生成任务完成。
- 通过率、节省时间和优化比例只在有运行记录时放入页面；没有实测值时使用“待实测”标记。
- 正式提交前逐页核对标题、数字、单位、住户称谓和模式名称：试住模式 Stay、实验室模式 Lab。
