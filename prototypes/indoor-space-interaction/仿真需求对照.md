# 仿真需求对照

对照来源：`测试模型/home-accessibility-main` 中的产品、仿真、标准和比赛验收文档。

## 已经可以直接使用

- 内置住宅、办公场景和本地导入模型都能进入同一套栅格通行仿真。
- USDZ、GLB、OBJ 等模型可导入；家具识别、相似模型列表、原位替换、朝向和缩放保持、相机保持已经接通。
- 任务驱动数字住户支持床、沙发、冰箱、卫生间、门等目的地；GPT 失败时自动本地解析，不再误用内置住宅坐标。
- 关节家具支持旋转轴、滑轨或 GLB 动画；人物靠近时可触发动作，并记录家具碰撞和受阻反馈。
- 手动轮椅、助行器、视障白杖、上肢受限、普通步行者已经有确定性任务轨迹和碰撞结果。
- 新增独立的电动轮椅画像：更长包络、更高速度、独立转向和门操作阻力，仍复用当前可靠的矩形扫掠判定。
- 核心任务 T1–T4，以及夜间起夜、急救担架、门口杂物容错任务包已经接入；规范报告会输出通过、失败或未检查、对象归因、测量值和标准依据。
- 修复 Agent 可以生成候选改动、复测并导出修改前后对比；火灾、地震和救援担架有可复现的降阶模型。

## 目前是“示意分析”或部分完成

- 夜间起夜已经有路径任务，但导入场景没有真实照度标定和灯具开关语义时，照度检查会明确标记为 `not_checked`。
- 急救担架使用 `0.60 × 1.90 m` 的矩形 SE(2) 扫掠，能给出最窄处和阻断物体；它不是 MuJoCo/PhysX 接触动力学。
- 门口杂物容错能按固定种子逐个放箱并报告首次阻断位置，属于几何容错实验。
- 视障住户已有白杖探测动作和路径探测记录，但还没有需求文档要求的突出物缺陷注入、召回率验收和完整标准映射。
- 标准报告已覆盖门宽、门把手、通道、转身、床侧转移、触达、门操作和门扫掠；完整 Scene IR 缺字段时会保留估算或未检查状态。

## 仍然有明显差距

- 没有完整的 WSR Scene IR 导入、批量户型库体检、批量生成住宅和家具系列成对评测工作台。
- 没有独立的陪护推轮椅双角色运动；当前电动轮椅是参数化画像，角色外观仍复用轮椅资产，也没有真实电机动力学。
- 没有真实商品目录抓取、SKU 参数核验、Lux3D 尺寸 QA 和商品系列批量建模。
- 没有从户型图自动生成 Scene IR 的完整入口。
- 没有真实照明、烟气 CFD、结构动力学和完整 MuJoCo 回放；这些需要额外数据、引擎和标定，不能只靠前端几何补齐。

## 验证结果

已通过：核心导航、仿真指标、标准报告、电动轮椅画像、USDZ 服务、浏览器主流程、住户回归、碰撞归因和办公场景六房间进入测试。

格式导入测试当前缺少 Rhino WASM 依赖；直接双击 HTML 的预览依赖上级共享 Three.js 目录，属于启动方式和运行时依赖问题，HTTP 本地服务流程不受影响。

## 推荐的后续顺序

1. 先补 Scene IR/WSR 批量入口和实验室结果汇总，这是与需求文档差距最大、也最影响产品化的一项。
2. 再补视障突出物缺陷注入与验收数据，形成可量化的 P1 证据。
3. 最后接入真实照度、MuJoCo/PhysX 或专业求解器；在此之前继续把这些结果标成示意分析。
