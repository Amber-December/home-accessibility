# ACCESS · 室内通行实验室

双击 `启动室内空间.bat`。优先使用 PATH 中的 Node.js，找不到时尝试 Codex 附带的 Node。默认 8910 端口；同一个应用已运行则直接复用并打开浏览器，被其他程序占用则自动尝试下一个端口。新启动的服务请保持终端运行；复用服务时新窗口可以正常结束。也可以在已运行的 InteractiveEarth 本地服务中打开 `/室内空间交互/index.html`。无需 npm 安装、联网或构建。

双击 HTML 使用 `file://`，读取的是文件系统；BAT 使用仅绑定本机的 `http://127.0.0.1` 本地服务。HTTP 有稳定的同源地址，能正常请求 3DM 的 WASM、Worker 及模型配套文件。直接打开 HTML 可以体验示例，但部分模型加载会受到浏览器本地文件限制。两种方式都在本机解析模型，不会把模型传到远程服务器。

## 使用

1. 默认进入「任务驱动数字住户」和可编辑住宅。可切换「自由探索」、办公空间或上传模型。空间透视、细节近景、平面分析、跟随住户和自由步入均可使用。自由步入时 WASD 移动、左键拖动看方向，E 开关附近的住宅门；手动探索会暂停任务，操作不计入任务报告。精细画质包含 SSAO、环境反射与柔和阴影。
2. 导入一个主模型，可多选配套材质/贴图/BIN。支持 OBJ+MTL、ASCII/二进制 STL、3DM、3DS、GLB/GLTF、FBX、DAE、USDZ。USDZ 由本机 OpenUSD 完整解析引用、实例、旋转和缩放后转换为 Y 向上米制 GLB；首次使用请运行「安装USDZ支持.bat」，浏览器通过 loopback 服务提交到本机，不上传远程。USDZ 默认 Z 向上。Rhino/STL/3DS 也默认 Z 向上，其余默认 Y；DAE 遵循加载器转换后的轴向。通过导入设置可覆盖。模型单位默认 m，Rhino 毫米模型请改 mm。更改后点击重新导入。
3. 任务模式的 DIY 画像支持两段自然语言：人物描述，以及一天行程。行程中的“床、沙发、冰箱、卫生间、入户门”等词会优先绑定当前内置住宅的语义实体，并按输入顺序排成目的地队列。选择「用 GPT-5.6 识别人物与行程」时，本地服务只把场景实体清单发给服务器端 AI 代理；没有配置 API 时自动回退本地关键词解析。
4. GPT 代理只从服务器环境变量读取密钥，禁止把密钥写入 `index.html`、浏览器脚本或仓库。PowerShell 启动前可设置：

   ```powershell
   $env:OPENAI_API_KEY = '<你的 OpenAI API Key>'
   $env:ACCESS_AI_MODEL = 'gpt-5.6'
   .\启动室内空间.bat
   ```

   若只想使用本地解析，不设置 `OPENAI_API_KEY` 即可。服务端会返回 503，前端自动继续本地解析，人物和目的地功能仍可用。
5. Lux3D 家具生成只在点击某一家具候选旁的「Lux3D 生成」后发生，避免自动批量消耗额度。国内区密钥只从运行时环境变量读取；在 PowerShell 中先设置 `LUX3D_CN_API_KEY` 和 `LUX3D_ALLOW_BILLABLE=1`，再双击「启动室内空间.bat」：

   ```powershell
   $env:LUX3D_CN_API_KEY = '<你的国内区 Lux3D Key>'
   $env:LUX3D_ALLOW_BILLABLE = '1'
   .\启动室内空间.bat
   ```

   生成完成后 GLB 会缓存在 `.cache\lux3d`，浏览器会按家具候选区的宽度、深度和合理高度自动缩放，并替换动态代理。未设置 `LUX3D_ALLOW_BILLABLE=1` 时只显示提示，不会发起计费请求。
6. 自动选取靠近模型底部的大型水平面作为地面。需要时填写「地面距模型最低点」米数覆盖。导入后务必检查平面大小、地板支撑与碰撞栅格。识别到足够地板时，仅地板区域可通行；没有时使用模型平面包围范围作为虚拟地面。
7. 行人为四类不同半径的圆盘（步行、轮椅、助行器、上肢活动受限），从各自身体尺度对应的最大连通通行区生成。局部视野避障、预测人群分离、全局栅格寻路、连续分步碰撞共同控制运动。搜索范围优先限定目的地；范围内没有目标时会寻找更远的目的地。所有代理使用相同已知平面地图，不模拟未知空间学习。
8. 添加或删除目的地、改变数量/构成/精度会清空旅程统计。速度、视野和搜索距离实时生效。暂停时视图仍可操作，切到后台暂停推进。
9. 导出 JSON（参数、指标、栅格、事件）或 CSV（全部栅格，可导入 GIS / Excel / GH）。导出坐标为居中后的 X / Z 米制坐标，不是原模型的绝对坐标。
10. 目的地模式可选「默认」「只使用自定义」「默认 + 自定义」。自定义支持「在地面点选」和输入名称、X/Z 坐标。添加时如果原先使用默认，会自动切到混合模式；只使用自定义但还没设置目标时，行人会等待。切换模式不会删除自定义目标；「恢复默认」重新启用所有默认目标并保留自定义列表。同一模型更改栅格精度会保留目标，导入新模型会重新建立目标。
11. 点击有颜色的磕碰栅格，可查看累计接触、障碍受阻、人际等待、原因、涉及家具或墙体、人群、身体包络宽度和时间。选中位置有红色框。点击事件列表也会定位并打开该栅格的详情。
11. 渲染风格提供三套演示：`ACCESS` 白蓝空间、`Editorial` 深色电影室内和 `Surreal` 柔光彩色空间。它们按墙体、地面、木作、织物、金属、卫浴和玻璃分组调整背景、环境光、色调映射与模型材质；精细画质再启用 SSAO、环境反射与柔和阴影。风格用于网页展示，不替代离线路径追踪。
12. 灾害实验会自动切换到「自由探索 · 模型通行与人流」并重新生成代理。火灾按温度、燃料、烟气、风向和墙体阻断更新传播场，代理按危险代价重新规划出口；地震按确定性地震动累计结构损伤，触发倒塌事件、碎片掉落和人群碰撞。可用强度滑块和 1× / 2× / 4× 查看传播过程。

## 数据含义与边界

- **接触**：代理的移动尝试与障碍安全半径重叠；不允许穿透，每人每秒最多记录一次。人际避让不计建筑接触。
- **受阻旅程**：目的地对当前身体半径不连通，或者连续停滞超过 3.5 秒（也可能因为人群拥堵）。每旅程一次，等待后另选目标。
- **默认磕碰热点**：障碍接触次数 + 障碍受阻次数，两个分项也可分别显示。画面不叠加人流密度、停留时间或近障暴露。已检测为人际避让造成的等待单独统计，不进入热点。
- **原因归属**：接触记录来自一次被碰撞系统阻止的实际移动尝试，包含当时碰撞到的栅格与模型对象。受阻记录来自无法连通的路径或持续停滞；附近障碍只提供定位线索，并不等同于实际接触面。详情中的门宽来自内置模型标注，导入模型未识别的网格会显示其名称。
- **问题面积 / 每百米磕碰**：分别为当前指标有事件的栅格面积，以及接触次数 ÷ 全体累计行走米数 × 100。颜色按本次最大值归一化，不能直接跨次比较。
- **到达率**：到达 / (到达 + 受阻旅程)，进行中的旅程不进入分母。
- **新增仿真质量指标**：每个 Agent 记录全程最小净空及发生位置/时间、规划路径与实际行走距离、绕行比、重规划次数、人群等待、几何等待和灾害暴露时间；状态转移和反应码（平静、发现灾害、保护、改道、疏散、受阻、安全）会写入事件流。
- **可复现运行记录**：JSON 现在包含 `manifest`（随机种子、栅格参数、灾害出口、画像参数和事件上限）、`agentMetrics`、`qualityChecks` 与按人群汇总的净空统计。自检会报告墙体穿透、人际重叠、越界、无效目标、灾害出口危险和动态家具越界。
- 统计来自实际步进模拟，不预填样本。重置使用固定随机种子；事件列表最多保留最近 5000 条，每个栅格另外保留累计原因聚合和最近 8 条详情。清空事件列表不会删除热点原因；清空热点会同时删除该层栅格原因聚合。行人轨迹默认关闭，可手动开启。

火灾与地震是确定性降阶模型，用于网页端可复现的方案比较和行为调试。火焰 Sprite、烟气 Sprite、倒塌碎片是视觉表达；它们不宣称等同真实 CFD、有限元结构动力学、刚体破碎或规范安全评估。工程级结果应把同一模型和边界条件导出到 Isaac Sim / PhysX、CFD 或专业结构求解器复核。

碰撞通过真实三角面截取距地面 0.08–1.80 m 区间并保守投影到栅格；每个网格参与碰撞，支持旋转和实例变换，不以全模型包围盒代替墙体。小于 2 m² 的封闭投影空腔被填实以防在空心家具内部生成行人；这也可能填掉小隔间，需查看碰撞栅格。栅格误差可造成窄门更早受阻，先提高精度并比较。统一人体高度无法准确表示可俯身或可钻入的空间。

仅支持一个水平地面；没有楼梯、坡道、落差、可通行高度分类和规范条文判定。自由探索使用圆盘身体；任务住宅另行实现矩形包络转向扫掠与可操作门。3DM 需保存可用的渲染网格；压缩 GLTF（Draco / Meshopt / KTX2）需先转为未压缩版本。普通模型限制 180 MB / 200 万三角面；完整 USDZ 允许到 600 万三角面，仍建议在 OpenUSD/Isaac Sim 中生成简化碰撞网格。栅格上限约 20 万格（大场景会自动降低分辨率）。外部纹理只从本次选择的本地文件读取，不发远程资源请求。

## 任务驱动数字住户

- 画像包含轮椅住户、助行器老人、视障白杖住户和上肢活动受限住户。宽度、包络长度、速度、水平及最高触达、归一化操作阻力阈值均可调整。默认值是演示假设，不能代表整类人群，也不是医疗或规范参数。
- 五项任务：入户到沙发、卧室到卫生间、取用冰箱、床椅转移、紧急疏散。每项独立重置起点和门状态，不把五项任务拼成连续生活轨迹。
- 导航搜索包含位置和 8 个朝向，平移和转向均检查矩形扫掠，允许倒退。门操作包含接近、触达、操作阻力、门叶扫掠、其他门叶冲突和退让位置检查。门框铰链处采用有限栅格留量，并非铰链力学仿真。
- 白杖画像假设熟悉住宅布局，沿已知任务路径执行局部三向白杖扫描，记录探测距离、构件及探测停顿；不模拟未知建筑自主建图或真实视障行为预测。
- 冰箱取物检查接近位置、把手高度和触达距离；床椅转移检查床侧包络空间。动画与几何判定不等同于人体动力学、抓握力学或辅助照护能力评估；疏散任务不含烟火蔓延。
- 记录包括独立的碰撞尝试、路径失败、转向失败、触达失败、开门失败、转移失败、最小包络余量、任务耗时和动作轨迹。导航拒绝穿透时是路径失败，不伪造一个碰撞事件。余量按已执行路径、身体包络和门叶计算；更高完成率不保证所有路径余量都增大。
- 「修复 Agent」是有边界的规则候选搜索，不调用外部大模型：移动床侧椅/茶几/洗手柜，替换低位把手冰箱，改变门的开启方向或易握执手参数。每个候选都重新建模、栅格化并执行同一任务集，最多 6 轮，只保留评分改善的修改。不会直接写入成功率；未修复的任务继续显示失败。
- 修改前后固定画像、任务、起点及精度。耗时改善只统计前后都成功的共同任务；失败尝试很短不表示更优。报告可导出完整配置、动作、探测、问题、候选审计与两套场景参数，可切换前后查看或还原。
- 商品替换是内置尺寸方案，非真实在售商品。自动任务、动作和修复当前针对有床/门/冰箱语义的内置住宅；导入模型仍可自由通行检测，不会自动把任意网格识别成可操作商品。

原办公场景无法进入房间的问题包含跨门洞装饰灯带被错误投影为障碍，南侧会议室的显示屏摆在入门通道上，以及接待椅挤占较大身体包络的入口转向空间。灯带已排除碰撞，显示屏移到背墙；寻路按真实圆盘与栅格方块测试，不再叠加额外的距离场膨胀。回归测试让单个行人从走廊实际进入六间周边办公房间（步行、轮椅、助行器共 18 个实际进入用例），未通过时不只依赖“路径存在”的判断。

## 架构

- `index.html` / `style.css` / `digital-twin.css`：中文控制台、全屏三维底图、悬浮面板和数字孪生主题。
- `js/core.js`：无 Three.js 依赖的精确欧氏距离变换、圆形碰撞、连通分区、Dijkstra 路由与栅格数据。
- `js/geometry.js`：世界坐标三角面提取、地面识别、人体高度裁剪、保守栅格化。
- `js/scene.js` / `js/office.js`：办公空间、PBR 材质、ACES 色调、柔和阴影、基于栅格烘焙的接触阴影近似、玻璃隔断、实例化家具与行人、轨迹和热力。
- `js/rendering.js` / `js/avatars.js`：SSAO、环境反射、Gamma / FXAA、关节人物、轮椅和助行器细节。`js/vendor/postprocessing` 使用 Three.js r128 官方示例（MIT），来源固定为 `https://github.com/mrdoob/three.js/tree/r128/examples/js`，运行时不联网。
- `js/vendor/Rhino3dmLoader.js`：Three.js r128 原有加载器的本地副本（MIT），只为本应用补充 Worker 异常回传，避免损坏 3DM 一直等待；未改动原项目加载器。
- `js/importers.js`：本地模型 / 配套资源解析、尺度 / 轴向 / 地面变换。
- `js/floorplan.js`：平面图像素识别、墙体 / 家具候选区、米制单层住宅 blockout 与动态家具代理。
- `js/simulation.js`：代理状态、目标选择、导航与避碰、动态家具、净空/路径质量指标、状态转移、失败归因、运行 manifest 和仿真自检。
- `js/fire-core.js` / `js/earthquake-core.js` / `js/disaster.js`：确定性火灾传播、地震损伤与灾害视觉层。
- `js/app.js`：状态绑定、导入流程、视图控制与导出。
- `js/home.js`：可编辑住宅、家具商品参数、可操作门、语义 ID。
- `js/resident-nav.js` / `js/resident-tasks.js`：朝向导航、身体扫掠、白杖扫描、任务动作评估与轨迹执行。
- `js/resident-repair.js` / `js/resident-workbench.js`：候选修复、重建复测、画像参数、前后量化对比和任务报告。
- `server.cjs`：无依赖本地服务，仅允许本应用和相邻 vendor 资源访问。
- `scripts/lux3d-service.cjs`：国内区 Lux3D 本地代理；Asset 上传、异步任务轮询、GLB 缓存和同源静态资源服务均在本机完成。

运行算法测试：`node tests/core.test.cjs`；启动器测试：`node tests/launcher.test.cjs`。浏览器测试需 Playwright，可设置 `NODE_PATH` 指向已安装的包，运行 `node tests/browser.test.cjs`、`node tests/accessibility.test.cjs` 或 `node tests/formats.test.cjs`；本地服务需先启动。

数字住户与房间入口回归：`node tests/resident-regression.test.cjs`。验证四种画像、白杖动作、全轨迹静态碰撞、固定起点前后修复、报告导出、门动画、手动步入和六个办公房间的实际进入。
